# 每日优惠线索

覆盖原部署包中的 20 家互联网平台，并增加 13 家银行/银联的信用卡优惠检索；自动采集近 7 天的公开优惠线索，生成可搜索的静态网页。每天北京时间 **10:30** 由 GitHub Actions 运行，结果写入 `index.html`、`data/latest.json` 和每日归档，随后发布到 GitHub Pages。

## 从原部署包提取的规则

1. **覆盖平台**：腾讯、阿里（淘宝/天猫）、字节（抖音）、美团、拼多多、京东、网易、百度、小米、快手、携程、滴滴、蚂蚁（支付宝）、B站、微博、360、唯品会、小红书、贝壳、东方财富。
2. **场景**：外卖/本地生活/餐饮、电商购物、出行/旅游/酒店、会员订阅与综合补贴、信用卡优惠。
3. **优惠信息字段**：平台、优惠内容、力度/门槛、有效期、领取方式、来源。原页面混合了长期权益与国庆限时活动，过期活动不应继续展示为“今日优惠”。
4. **可信度**：原页面区分“已查证”和“一方称”。自动采集器读取公开 RSS 标题、摘要、发布日期和来源；摘要字段可能只是标题复述。单一来源一律标记“一方称”，不会自动标记“已查证”。
5. **合法性**：只检索公开正规优惠，不采集违规套利、账号买卖或绕过资格限制的信息。

## 每日采集与筛选

- 对每个平台检索公开新闻 RSS，关键词按场景扩展，信用卡板块额外检索消费立减、积分抵现、免年费、免息和免密支付。
- 只保留标题中同时含平台名称和优惠词、发布时间在北京时间近 7 天内的结果；剔除口令推广、领取攻略、尚未开始的双十一预热信息，按标题相似度去重，每个平台最多展示 5 条。
- 首页展示“今日 TOP10”数字线索和明确截止日期的临期活动，并按五个生活场景分组。TOP10 仅按标题中可见的数字排序，不代表跨品类性价比。字段只从 RSS 标题/摘要中的明确文本提取；入口和使用步骤目前不自动猜测，无法确认时显示“报道未说明”。
- 若全部采集失败，程序报错并保留旧页面；部分失败会在页面和 JSON 中记录。零结果会明确显示“无符合规则的线索”。
- Google News RSS 的收录、排序和可访问性由第三方控制；部分 App 内优惠不在公开网页上，因此本页不保证穷尽或实时可领。

## 历史翻阅与查询

- 每次成功采集都把结果保存到 `data/archive/YYYY-MM-DD.json`。同一天手动重跑会更新该日归档，不会新增重复日期。
- `data/catalog.json` 汇总所有归档供网页查询；网页默认显示最新一天，可用“较早 / 较新”、日期菜单翻阅，也可选“全部历史”后搜索平台、标题或来源。
- 日期会写入网页地址，例如 `?date=2026-10-07`，方便收藏或分享。历史日期指**采集日期**，卡片另列报道发布日期；历史线索不代表现在仍有效。
- 结构化历史从 **2026-10-07** 开始。此前的国庆静态页面没有每日采集数据，不会伪造为历史记录。

## 本地运行

需要 Python 3.12+，无第三方依赖：

```bash
python collect.py
```

可用 `python collect.py --output /path/to/index.html --json-output /path/to/latest.json` 写入其他位置。运行后用浏览器打开 `index.html`。

## GitHub 部署

将仓库推送到 GitHub 后，在仓库设置的 **Pages → Build and deployment → Source** 选择 **GitHub Actions**。首次在 Actions 页面手动运行“每日优惠采集与网页发布”，成功后打开 Actions 输出的 Pages 链接。仓库设置中的 Actions 工作流权限需允许读写，以保存每日数据。

GitHub 的定时任务可能延迟；若需要固定时间的即时结果，可手动运行工作流。

原部署包 `2026-10-06` 的页面是节日快照，自动运行后首页会替换为当前日期的公开线索。程序不会把旧活动冒充为仍有效的优惠。
